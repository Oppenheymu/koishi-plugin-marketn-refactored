## 3. 关键架构约定（P3 必须遵守）

1. **core 层禁 koishi 运行时 import**：只允许 `import type { Dict } from "koishi"`；`Context/Service/Logger/HTTP/Time/Schema` 一律不进 core。I/O 通过构造函数注入（`deps` 对象）。check-size 脚本的 `checkCoreImports` 会 grep 校验。
2. **依赖方向**：`environment`、`upload` 无内部依赖；`install` → `deps`/`registry`/`racing`/`environment`/`upload`。不要反向。
3. **竞速/并发三件套**：`RequestScope`（serial 陈旧性 + AbortController）、`RouteStatsBook`（端点学习评分）、`raceEndpoints()`（错峰竞速骨架）。P3 组装时把 `RequestScope` 的 `isActive` 接到 `ctx.scope.isActive`。
4. **execa v10 适配（重要）**：旧代码 `import spawn from 'execa'` 是老版 API，P0 已把 execa 升到 v10，**默认导出已不存在**。本次已适配：
   - `install/runner.ts` 的 `runPackageManager()`：`execa(name, args, { cwd, reject: false })` + `subprocess.stdout/stderr.on('data')` 流式逐行解析（yarn berry `--json` 走 `exec-parse.ts` 的 `yarnLogLevel`）；exit code/signal 从 `result.exitCode/signal` 取。
   - `install/upload.ts` 的 `prepareLocalBinding()`：`const { stdout } = await execa("npm", [...], { cwd, timeout })`。
5. **agent 检测注入（bug 修复）**：旧代码 `private agent = detect()` 未 await（永远退回 npm）。现在 P3 适配层必须 `await detect()` 后把 `{ name, version }` 注入 `PackageManagerAgent`（见 runner.ts）。`detect` 来自 `package-manager-detector`，返回 `Promise<DetectResult | null>`。
6. **market/source.ts 三分**：`source.ts`（状态+拉取+collect+start）、`background.ts`（`MarketBackgroundRefresher`：refresh/probe 后台编排）、`source-host.ts`（`createSourceSnapshotHost()` + `performanceFrom()`）。P3 的 `MarketProvider`（DataService）直接构造 `MarketIndexSource` 即可。
7. **参数属性禁用**：tsconfig 开了 `erasableSyntaxOnly`，构造器不能用 `constructor(private x)`，必须显式字段 + 赋值。
8. **`noUncheckedIndexedAccess` / `exactOptionalPropertyTypes` 已开**：`Dict<string>[key]` 返回 `string | undefined`，`hasOwn` 之后要 `!`；可选属性赋值不能带 `undefined`（用 `?? null` 或加 `| undefined`）。

## 4. P3 接线核心：各服务的构造 deps（精确签名）

P3 的 `installer.service.ts` 门面负责组装。以下是 core 各「入口类」的 `deps` 字段（以源文件为准）：

### 4.1 InstallOrchestrator（`install/orchestrator.ts`，公开方法：`install` / `installLocked` / `refreshDependencyState` / `captureCurrentEnvironmentSnapshot` / `recordCurrentEnvironmentSnapshot` / `isInstalling`）

```ts
{
  cwd: string,
  log: InstallLogger,                       // { debug, info, warn, error }（warn/error 收 unknown）
  config: { endpoint?, timeout? },
  scope: RequestScope,
  registry: RegistryClient,
  packages: PackageCache,
  resolver: DependencyResolver,
  environments: EnvironmentSnapshotStore,
  queue: InstallQueue,
  logs: InstallLogStore,
  agent: PackageManagerAgent | undefined,  // await detect() 后注入
  refreshChannels: () => Promise<unknown>,          // console.refresh ×4
  refreshDependenciesChannel: () => Promise<unknown> | undefined,  // console.refresh('dependencies')
  clearRegistryStatus: () => void,          // 清状态 + broadcast('market/registry-status/clear')
  fullReload: () => void,                   // ctx.loader.fullReload
  isActive: () => boolean,                  // ctx.scope.isActive
  isPackageLoaded: (name) => boolean,       // require.resolve(name) in require.cache（含解析失败→true）
}
```

### 4.2 EnvironmentSnapshotOps（`install/environment.ts`，公开：`getEnvironmentSnapshots` / `getEnvironmentSnapshotPreview` / `applyEnvironmentSnapshot`）

```ts
{ log, environments: EnvironmentSnapshotStore, queue: InstallQueue, orchestrator: InstallOrchestrator }
```

### 4.3 LocalPackageUploadService（`install/upload.ts`，公开：`start/append/finish/commit/cancelLocalPackageUpload` / `prepareLocalBinding`）

```ts
{ cwd, log, timeout?, uploads: LocalPackageUploadStore, resolver: DependencyResolver }
```

### 4.4 InstallLogStore（`install/logs/store.ts`，公开：`start` / `emit` / `finish` / `activeFile` / `activeMetadata` / `waitForWrite`）

```ts
{ cwd, log, retention: InstallLogRetention, broadcast: (type, line) => void, resolveAfter: (name) => string | undefined }
```

- `retention` 构造：`new InstallLogRetention(cwd, () => getInstallLogRetention(config), log)`。
- `broadcast` 接到 `ctx.console.broadcast('market/install-log', ...)`。
- `resolveAfter` 接到 `(name) => depCache[name]?.resolved`（回填 afterResolved）。

### 4.5 日志读取（`install/logs/reader.ts` 的纯函数）

```ts
getInstallHistory(limit, { cwd, log, activeFile, waitForWrite, cleanup })
getInstallLogDetail(id, { ...同上 })
```

- `activeFile: () => logs.activeFile`；`waitForWrite: () => logs.waitForWrite()`；`cleanup: () => retention.cleanup(logs.activeFile, logs.activeMetadataFile)`。

### 4.6 RegistryClient / PackageCache / DependencyResolver（P2-1 已建成，P3 组装）

- `RegistryClient(deps, config)`，deps：`{ httpFactory, isHttpError, stats: RouteStatsBook, statsFile: JsonStore, scope: RequestScope, defaultEndpoint: () => Promise<string>, statusSink, log }`。`statusSink(name, status, serial)` 接到 `setRegistryStatus` 的 channel 刷新/广播；`defaultEndpoint` 接到 `getRegistry()`。
- `PackageCache({ client, scope, log, onFlush })`；`onFlush` 接到节流后的 `broadcast('market/registry', tempCache)`。
- `DependencyResolver({ cwd, cache: PackageCache, scope, concurrency, formatError, ensureProbe, log, onMetadataRefreshed })`；`formatError` 接 `registry.formatError`；`ensureProbe` 接 `registry.ensureMetadataEndpoint`；`onMetadataRefreshed` 接 `console.refresh('dependencies')`。

### 4.7 MarketIndexSource（`market/source.ts`，P3 的 MarketProvider 直接构造）

```ts
new MarketIndexSource({
  http: (endpoint) => ctx.http.extend({ endpoint, timeout }),   // 按端点创建 HTTP
  scannerRequest: (url, config) => ctx.http.get(url, config),   // Scanner 的网络请求
  cacheFile: resolve(ctx.baseDir, 'cache', 'market-next-index.json'),
  cacheDir:  resolve(ctx.baseDir, 'cache', 'market-next-index'),
  log, notifyRefresh: () => ctx.console.refresh('market'),
  broadcastPatch: (payload) => ctx.console.broadcast('market/patch', payload),
  onRegistryVersions: (name, versions) => installer.setPackage(name, versions),
}, marketConfig)
```
