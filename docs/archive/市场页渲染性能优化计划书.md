# 市场页渲染性能优化计划书

> 状态：**待执行**（供新对话研究并处理，完成后本文件移入 `docs/archive/`）。
> 现象：插件市场页上下滑动时**微微掉帧/稍卡**。目标：让滚动保持 60fps，无掉帧感。

## 0. 背景（已在主对话初步定位，供新对话深入）

市场页 = `client/market/components/list.vue`（虚拟滚动）+ `package.vue`（卡片，686 行含头像子系统）。虚拟滚动本身已实现（窗口内只渲染可见卡片 + overscan），但滚动时仍有掉帧，疑似以下三处开销叠加：

1. **卡片无 `v-memo`**：`list.vue` 模板 `v-for="data in renderedPackages"` 渲染 `<market-package>`，滚动时窗口内卡片对象引用未变，但 Vue 仍会对它们做 diff + 头像 props 响应式更新。
2. **滚动路径上有强制同步布局**：`updateVirtual` 滚动帧内无布局读取，但 `ResizeObserver` 触发 `measureLayout`（`getComputedStyle`/`querySelector`/`getBoundingClientRect`），可能造成 layout thrashing。
3. **入场动画在滚动中触发**：`settled` 700ms 延迟置 true 后卡片有入场动画（`deps-polished-enter`/`market-polished-card-enter` 等），滚动时窗口移动频繁触发动效。

## 1. 待研究/验证的方向（按性价比排序）

### A. `v-memo`（零风险、最高收益，建议先做）
- `list.vue` 模板给 `<market-package>` 加 `v-memo="[data.package.name]"`——窗口内卡片数据未变时跳过 diff。
- 验证：滚动时卡片是否仍需要响应 `gravatar`/`debug` 变化（若需要，`v-memo` 数组加对应项）。

### B. 头像子系统优化
- `package.vue` 的头像候选链 + 失败降级 + `requestIdleCallback` 水合：确认**滚动帧内不会跑**（水合应只在空闲时）。
- 若头像在滚动中触发 fetch/缓存查找，考虑降低频率或加节流。

### C. 消除滚动路径的强制同步布局
- `measureLayout` 里的 `getComputedStyle`/`querySelector`/`getBoundingClientRect` 只在**数据/尺寸变化时**跑，滚动时不做。
- 确认 `ResizeObserver` 回调里没有读布局导致 thrashing。

### D. 动画与滚动解耦
- 滚动时（`scheduleVirtual` 触发）暂时关闭入场动画，滚动停止后再恢复（或 `content-visibility: auto`）。
- 注意与虚拟滚动叠加的冲突（`content-visibility` 可能影响 spacer 高度测量）。

## 2. 验证方法

- **量化**：DevTools Performance 面板录制滚动，看主线程占用（目标：滚动期间 <16ms/帧）、Layout/Recalculate 时间。
- **对比**：改前改后各录一次，对比卡顿率。
- 若 `debug` 面板可用（市场页 debug 卡），看 `frontendVirtual` 耗时变化。

## 3. 验收标准

- 滚动期间主线程无明显长任务（>50ms 的 task 数量大幅下降）。
- 掉帧感消失（用户主观验证：上下滑动顺滑）。
- `yarn check` + `yarn build:client` 全绿，产物名 `dist/index.js`/`dist/style.css` 不变。

## 4. 注意

- 只改 `client/market/components/` 与相关 scss，不动契约面（`client/index.ts`、导出面、产物名）。
- 改动尽量小步、可回退；每步验证后提交（简体中文）。
- 若 `v-memo` 后仍有卡顿，再按 B/C/D 逐项排查，**不要一次性全上**（难定位回归）。
