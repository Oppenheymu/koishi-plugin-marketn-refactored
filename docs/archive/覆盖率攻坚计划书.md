## 2. 统一测试策略（所有 sub-agent 遵循）

- **不引真实 Koishi 运行时**：`src/node` 是适配层，mock ctx（`baseDir`/`loader`/`logger`/`scope`/`console`）；引用 `Context` 一律 `import type`（vitest node 环境无 koishi 运行时）
- **不引真实网络/文件**：所有 IO（`fsp`/fetch/http）都 mock，返回可编程结果（坏 JSON / ENOENT / 超时 / 失败）
- **时序敏感点**（防抖写盘 setTimeout 0 / 竞态 / 轮询）：`vi.useFakeTimers()` + `await vi.advanceTimersByTimeAsync(0)` 精确推进
- **纯函数优先**：无 DOM/无 Vue 依赖的模块直接测；有依赖的用 mock 注入
- **DataService 子类**：优先真实类 + 最小 ctx；实例化困难再 mock 基类（`class FakeDataService { constructor(public ctx: any) {} }`）
- **测试文件位置**：`src/**/__tests__/*.test.ts`（vitest.config include 已含 `src/**/*.test.ts`、`client/**/*.test.ts`，node 环境）；`__tests__` 目录不算 check-size 行数门禁
- **风格**：4 空格、双引号、行宽 100、尾逗号、`import type`；测试注释简体中文

## 9. 注意（避免踩坑）

- client 测试是 node 环境（vitest.config `environment: 'node'`）——**别引 DOM**；`.vue` 不经 tsc 但测试要能加载纯 TS 模块
- `@koishijs/client` 的全局（store/send/Context）在测试里**必须 mock 或 stub**，否则 import 即炸
- `src/node/` 引用 `koishi` 的运行时符号（Context 等）**用 `import type`**，测试不加载真实 koishi
- 文件行数 ≤200（除非论证）；`__tests__` 不计行数门禁
- 若某模块（如 `installBundle`）依赖 `src/core/install` 重型流程，注入 mock 回调而非真实安装器
- 覆盖率以**语句覆盖**为主口径（分支/函数/行作辅助）
