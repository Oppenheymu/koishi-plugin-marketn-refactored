# 1. Client 端如何被构建与加载

## 1.1 addEntry 的完整参数（旧代码）

`C:/Dev/Bot-Dev/koishi-app/external/marketn-refactored/Waiting_refactored/src/node/index.ts:1548-1551`：

```ts
ctx.console.addEntry({
  dev: resolve(__dirname, '../../client/index.ts'),
  prod: resolve(__dirname, '../../dist'),
})
```

- 路径基准：无论从 `src/node/index.ts`（开发）还是 `lib/node/index.js`（构建后）算，`../../` 都正好是仓库根，即 `client/index.ts` 与 `dist/`。
- 另有 browser 端入口 `Waiting_refactored/src/browser/index.ts:23-30`（用 `KOISHI_BASE` 环境变量回退到 `/dist/index.js`，否则 `import.meta.url` 替换成 `/client/index.ts`）——这是 package.json `exports.browser` 对应物，与 console entry 是两回事。

## 1.2 运行时如何解析 entry（宿主端，已读源码确认）

- `@koishijs/console/lib/index.js:239-241`：`addEntry` 只是注册 Entry；真正解析在 `@koishijs/plugin-console/lib/node/index.js:114-135`：
  - `getFiles`：对象参数时，`!config.devMode → files.prod`；devMode 且 `existsSync(files.dev)` → `files.dev`，否则 `prod`。
  - `resolveEntry`：devMode 下 URL = `"/vite/@fs/" + 本地绝对路径`（即 client/index.ts 由 vite 中间件实时编译）；非 devMode 下 URL = `uiPath + "/@plugin-" + entryKey`，目录型 entry 自动补 `/index.js`，且**只额外探测 `style.css`**（第 129 行）。
  - `serveAssets`（同文件 136-160 行）把 `/@plugin-<key>/...` 静态映射回本地文件。
- devMode 默认值 = `process.env.NODE_ENV === 'development'`（`plugin-console/lib/node/index.js:286`）。宿主 `koishi.yml:32-33` 的 `console:oyzgdk` 只设了 `open: true`。
- dev 的 vite server 由 `createVite()`（`plugin-console/lib/node/index.js:208-220`）调用 `@koishijs/client/lib` 的 `createServer`，root 是 `@koishijs/client/app`，挂在 `/vite/`。

## 1.3 旧 client 构建脚本（git `432f0cb^:build.mjs`，初始提交时删除）

- node/shared/browser 用 esbuild 打到 lib/，其中 **node 端是 `format: 'cjs'`**——这就是旧代码能用 `__dirname` 的原因。
- client 用官方打包器：`const { build: buildClient } = require('@koishijs/client/lib'); buildClient(process.cwd(), { build: { target: 'esnext' }, esbuild: { target: 'esnext' } })`。
- 末尾把 `dist/index.css` 复制为 `dist/style.css`（因为 prod 目录 entry 只探测 style.css）。

宿主现有 `@koishijs/client@5.30.11` 的 `build()`（`C:/Dev/Bot-Dev/koishi-app/node_modules/@koishijs/client/lib/index.js:44-115`）已经改用 **vite**：入口固定 `<root>/client/index.ts`、输出 `dist/`（`index.mjs` 重命名为 `index.js`）、external 仅 `vue/vue-router/@vueuse/core/@koishijs/client`、内置 `@vitejs/plugin-vue` + `@maikolib/vite-plugin-yaml` + `unocss/vite(preset-mini, preflight:false)`、alias `vue-i18n→@koishijs/client`、`@koishijs/components→@koishijs/client`、scss modern-compiler。它自带依赖：vite ^5.4.10、unocss ^0.65.1、@vitejs/plugin-vue ^5.1.4（`@koishijs/client/package.json`）。

## 1.5 `virtual:uno.css` 来源

- 唯一引用：`Waiting_refactored/client/index.ts:24`。全 git 历史无任何 `uno.config.*`。
- **不需要新增配置**：dev 模式由宿主 console vite server 的 `unocss/vite` 解析，prod 由 `@koishijs/client` 的 `build()` 解析（两处都在 `@koishijs/client/lib/index.js:83/139`）。但若重写改用自己的 `vite.config.ts` 构建 client，就必须自己装 unocss 并注册（当前插件 package.json **没有** unocss 依赖）。

# 2. 宿主集成

- 宿主是 yarn4 workspace（`C:/Dev/Bot-Dev/koishi-app/package.json` workspaces 含 `external/*`），插件已链接：`node_modules/koishi-plugin-marketn-refactored` → symlink → `external/marketn-refactored`。
- **`koishi.yml` 里没有 marketn-refactored 条目**。`group:console` 启用的是旧包 `market-next:hgaird`（`koishi.yml:43-45`，npm 实体目录 `node_modules/koishi-plugin-market-next`，非 symlink）。host package.json dependencies 也只有 `koishi-plugin-market-next: 3.6.2`。→ 重写后必须在 koishi.yml 加条目（如 `marketn-refactored:xxxx:`，ns-require 自动补 `koishi-plugin-` 前缀解析到 symlink），并先禁用旧 `market-next` 避免页面/服务冲突。
- 无其他 external 插件依赖它（全宿主搜索仅自身 package.json 命中）。但旧 client 有大量 **self-import**：`client/index.ts:3`、`components/install-history.vue:108` 等从 `'koishi-plugin-marketn-refactored'` 导入类型——依赖 exports 的 types（`lib/node/index.d.ts`，需构建存在）或宿主 tsconfig paths。
- 解析模式（关键）：宿主 `dev` 脚本是 `cross-env NODE_ENV=development koishi start -r esbuild-register -r yml-register`，**没有 `--conditions development`**。加载链是 `@koishijs/loader` → `ns-require` → 原生 `require.resolve`（conditions 只有 node/require）。实测（node 24）：无 condition 解析到 `lib/node/index.js`；带 `--conditions development` 才解析到 `src/node/index.ts`。即 `package.json` 的 `exports.development` 字段**在当前 dev 脚本下不生效**，`yarn dev` 也必须先构建 lib/。
- 宿主 `yakumo.yml` pipeline `build: [tsc, esbuild, client]`，并注册了 `@koishijs/client/lib` 的 yakumo `client` 命令：对每个 workspace，只要 deps/devDeps/peerDeps 含 `@koishijs/client` 就执行 buildClient（本插件满足），也支持 `pkg.yakumo.client` 指向自定义 vite 配置模块（`@koishijs/client/lib/index.js:183-210`）。
- 宿主 `tsconfig.json` paths：`"koishi-plugin-*": ["external/*/src", ...]`（类型层面把包名映射到 src）。`group:develop`（$if NODE_ENV=development）启用了 `hmr:hlrb8i`。

# 3. tsconfig 与路径（插件仓库）

- `tsconfig.json:41-43`：`include: ["src"]`，`noEmit: true`，module NodeNext。`Waiting_refactored/` 不在 include 内且被 `.gitignore` 忽略（biome `vcs.useIgnoreFile: true` 同样忽略）→ 不影响 tsc/biome。
- 但重写后的 `client/` 也不在 include 内；旧仓库另有 `Waiting_refactored/client/tsconfig.json`（`types: ["@koishijs/client/global"]`，include "."）——client 需要独立 tsconfig 才有类型检查。biome `files.includes` 只覆盖 `**/src/**` 的 ts/js，不含 client 和 .vue。
- `tsdown.config.ts`：三个 entry → `lib/{node,browser,shared}`（全 esm+dts）。两个坑：
  1. **`__dirname`**：tsdown 0.22.14 的 `shims` 默认 `false`（`tsdown/dist/options-C1CN2x0L.mjs:627`），ESM 输出不注入 `__dirname`；旧 addEntry 用了 `resolve(__dirname, ...)`。需在 tsdown.config.ts 设 `shims: true` 或改用 `import.meta.url`。
  2. exports `node` 指 ESM 文件且 `type: module`，loader 用 `require()` 加载 → 需 Node ≥20.19（engines 已声明，宿主实际 Node 24.16，require(esm) 可用）。
- **当前 scripts 只有 `"build": "tsdown"`**：没有任何 client/dist 构建步骤——prod 模式 console 会 404。要么像旧 build.mjs 那样调用 `@koishijs/client` 的 build，要么靠宿主 `yarn build` 的 yakumo client 步骤。
- 新 devDeps（vite@8、vitest@4、eslint@10、@vitejs/plugin-vue@6、typescript@7）**尚未安装**：插件 node_modules 只有 `@types` + `undici-types`；宿主 root hoisted 的是 vite 5.4.21 / @vitejs/plugin-vue 5.2.4 / typescript 5.9.3，eslint 与 vitest 缺失。需先 `yarn install`。注意 dev 模式 console 实际用的是 `@koishijs/client` 内置的 vite 5，不是 vite 8。

# 4. 校验"能跑"的最短路径

1. 宿主 root `yarn install`（装入新 devDeps）。
2. `yarn workspace koishi-plugin-marketn-refactored build`（tsdown 产出 lib/，否则 loader 解析 `lib/node/index.js` 直接 MODULE_NOT_FOUND——已实测）。
3. 编辑 `koishi.yml`：注释掉 `market-next:hgaird`，在 group:console 下加 `marketn-refactored:<随机id>: {}`。
4. 宿主 `yarn dev`：console devMode 自动为 true（NODE_ENV=development），`addEntry` 的 `dev` 生效（要求 `client/index.ts` 存在），浏览器访问 `http://127.0.0.1:<port>/`（uiPath 默认空串，`console:oyzgdk` 的 `open: true` 会自动开浏览器）；client 由 `/vite/@fs/...` 实时编译，`virtual:uno.css` 由宿主 unocss 解析——**此路径无需构建 dist/**。
5. prod 校验（可选）：需 `dist/index.js` + `dist/style.css`（注意 prod 只探测 style.css），可用宿主 `yarn build`（yakumo client 步骤）生成，然后 `yarn start` 走 `/@plugin-<key>/index.js`。
