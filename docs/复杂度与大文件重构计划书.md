> 状态：**待执行**。这是给 LLM 会话（GLM5.3 + sub-agent）的长期任务书，目标是把项目的**复杂度重灾区**与**超限大文件**系统性治理掉，门禁全绿、契约面不变。
> 依据：2026-08-25 全量实测（`yarn check` 全绿 + fallow health 87 A + 17 个大文件清单）＋源码通读。

- **fallow health**：87 A，149 项超阈值（**44 critical + 35 high + 70 moderate**）。
  - ⚠️ `.fallow/*.json` 缓存是 **2026-08-21** 的旧快照（client 侧 `use-card-view.ts` 等路径已不存在），开工第一步先重跑 `yarn fallow health --format json` 取新基线，以新报告为准。
- **大文件**：src 侧 17 个文件 >250 行（见 §2 清单），其中 0 个 ≥350（暂无 fail 风险，但都需拆分或登记理由）。

## 1. 任务目标（可量化验收）

1. **结构**：§2 清单 17 个文件中，至少 12 个拆分到 ≤250 行；其余登记「不拆理由」到本文件 §5。
2. **复杂度**：fallow critical 从 44 降到 ≤15；health 分数从 87 提到 ≥90。
3. **质量**：`yarn check` + `yarn build` + `yarn test` 三绿；覆盖率不下降（以 86.9% 语句为底线）。
4. **契约**：对外契约面**零改动**——DataService 通道 / RPC / 广播 / HTTP 路由 / 命令 / 导出面（`client/index.ts`、包名导入的全部类型）原样保留。
5. **认知**：把「真重构对象」与「数据驱动映射（豁免登记）」的甄别结论固化到本文件 §4/§5，避免后人重复纠结。

## 4. sub-agent 编排建议（GLM 主对话开）

> 目标：一个主对话吃满免费 sub-agent，并行做互不碰文件的模块。

```
主对话：定基线（重跑 fallow + yarn check）→ 派发 → 汇总（全量 check/build/test）→ 收尾登记 §5
├─ sub-agent A → src/shared/（bundle.ts #1 + types.ts #17 评估）
├─ sub-agent B → src/core/market/（source #3 + cache #11）
├─ sub-agent C → src/core/install/（executor #6 + logs #8 + logs/store）
├─ sub-agent D → src/core/upload/（session #2 + local-binding #14）+ src/core/environment（#10）
├─ sub-agent E → src/core/registry/（fetch #12 + index #13）+ src/core/deps（#7）
├─ sub-agent F → src/node/（market/bundle #5 + data-store #4 + avatar #15 + console）
└─ sub-agent G → client 复杂度（filter.ts validate + use-bundle-members + use-package-card-status 查表改造）
```

- 每个 sub-agent **只读自己的模块 + 只改自己的文件/__tests__**，互不碰文件（按目录划界，天然无冲突）。
- 主对话每收一个 sub-agent 结果就跑一次 `yarn check`（必要时 `yarn build:client` 验 .vue import），全部完成后跑全量三绿。
- sub-agent 需要调研时让它自己开 sub-sub-agent 或并行读文件，主对话只做整合与门禁。

## 7. 给执行者的灵活度说明（重要）

- **本计划书是方向不是死命令**：拆分边界、函数粒度、豁免判定都以你调研后的判断为准；计划书里的行数/方案是初稿，发现更好的拆分方式尽管改。
- **不要为了降分而强行抽象**：数据驱动映射（状态→文本/图标）拆函数没有收益时，登记豁免比硬重构更正确；`.fallow` 缓存旧了，一切以重跑结果为准。
- **契约面是红线**：DataService/RPC/广播/HTTP/命令/导出面绝不能动；不确定某导出是否被外部消费时，查 `docs/reference/前后端调用契约.md` 或保守 re-export。
- **小步提交**：每完成一个模块跑一次门禁并提交，方便回退与评审。
- **遇到 Biome JSON 行尾不可见字符噪音**：已知无害现象，跳过即可（见 DEVELOPMENT.md §6.12）。
