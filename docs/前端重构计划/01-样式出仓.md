# 前端重构计划 01 · 样式出仓（样式提取专项）

> 状态：**计划定稿，待执行**。范围：`client/` 全部内联 `<style>` 块提取为同目录 `.scss`。
> 硬约束：**外观与功能零变化** —— 不编辑任何 CSS 规则内容，不改模板/脚本，产物逐字节可验证。
> 前置阅读：docs/P4-PORTING-GUIDE.md §2.3（样式出仓既有约定）、docs/design/P4-client移植设计.md §3.6。

---

## 1. 定位与目标

当前 `client/` 是扁平单文件形态，26 个非图标 vue 中有 **21 个文件携带内联样式，共 24 个 style 块、6,157 行**（占 vue 代码近 49%）。样式出仓是本轮前端重构的**第一优先批次**：

1. **零风险**：样式文本逐字搬运到外部 `.scss`，SFC 编译管线（vue plugin → sass → postcss → style.css）与 scoped 语义完全等价，唯一需要证明的是产物一致——本计划用**产物字节 diff** 做硬门禁（见 §7）。
2. **最大单点收益**：一次性清掉一半的 vue 行数，后续组件拆分（package.vue → card/row/dialog 等）不再被千行 style 块拖累。
3. **纯机械**：每个文件是独立可回滚的原子操作，不引入任何行为变化。

**本计划不做**（边界，见 §9）：CSS 内容清理/合并、class 重命名、组件拆分、逻辑下沉、死代码清理。

## 3. 约定（目标结构与命名）

**放置**：与组件同目录、同名 `.scss`（扁平结构下最机械，路径即组件名）。

**单块文件**：

```vue
<!-- 原：<style lang="scss"> 或 <style lang="scss" scoped> -->
<style lang="scss" src="./<name>.scss"></style>            <!-- 非 scoped -->
<style lang="scss" scoped src="./<name>.scss"></style>      <!-- scoped -->
```

**双块文件（仅 package.vue）**：两个 `.scss`，**保持原块顺序**（第 1 块 913–1068 行全局对话框样式 → 第 2 块 1070–1698 行卡片/列表行）：

```vue
<style lang="scss" src="./package.scss"></style>            <!-- 原块 1：全局对话框样式（非 scoped，必须保持全局） -->
<style lang="scss" scoped src="./package-scoped.scss"></style>  <!-- 原块 2：卡片/列表行（scoped） -->
```

**目标树（新增 22 个 .scss，不改动任何现有文件结构）**：

```
client/
├── components/          package.scss, package-scoped.scss, bundle-install.scss,
│                        dependencies.scss, market.scss, install.scss,
│                        install-history.scss, environment-versions.scss,
│                        install-progress.scss, confirm.scss,
```

## 4. 执行规则（每个文件的机械操作手册）

对清单 §2 中每个文件，执行且仅执行：

1. **读**原 `<style …>…</style>` 块，**逐字**复制正文（保留所有注释、空行、缩进、换行符风格；**禁止顺手格式化或"顺手修复"任何规则**）。
2. **新建**同目录 `<name>.scss`，写入上述正文（文件末尾换行与仓库习惯一致即可，不影响产物）。
3. **替换**内联块为 `<style lang="scss" [scoped] src="./<name>.scss"></style>`：
   - 保留原 `scoped` 有无；`lang="scss"` 保持。
   - 单块文件：标签落在原块位置即可（vue 允许 style 块出现在 script 之后）。
   - package.vue：两个标签按原顺序（先非 scoped 后 scoped），中间空行照旧。
4. **不改动**模板、script、props、class 名、i18n key 等任何其他内容。

**禁止事项**：不重命名 CSS class/变量/keyframes；不合并重复规则；不删"看起来没用"的规则；不改 `:deep`/`:global` 写法；不改 `url()`（本仓库无）；不做任何"顺手优化"。

## 5. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| scoped + src 语义 | Vue SFC 对 `<style scoped src>` 与内联 scoped 走同一编译管线（postcss 加 `data-v-*`），scopeId 由 **.vue 文件路径**决定、与 .scss 位置无关，scoped 内 keyframes 的哈希后缀不变 | 无需特殊处理；产物 diff 兜底 |
| 全局（非 scoped）块 | 每组件一个全局块（el-dialog 覆盖、动画容器等），移出后仍是全局，**不得**给它们加 scoped | 保留 scoped 属性原样；package.vue 的全局段尤其注意 |
| style.css 内块顺序 | 输出顺序由模块 import 图决定（index.ts → 组件），提取不改变 import 图 → 顺序不变；全局块之间顺序影响级联（如两处 el-dialog 覆盖） | 不改 import；包块顺序照搬；产物 diff 验证 |
| `:deep` / `:global` | 照搬即等价（vue compiler 对外部文件同样转换） | 逐字复制 |
| keyframes 命名 | scoped 内自动加哈希；全局块保持原名（跨组件同名是既有行为，不新引入） | 不改名 |
| 行尾/编码 | sass 编译对源文件空白不敏感，产物不受影响 | 复制正文时保留即可 |
| 双块文件顺序 | package.vue 先全局后 scoped，两个标签顺序错位会改变输出顺序 | 操作手册第 3 步明确保序 |
| dev 模式 | 宿主 console vite server 实时编译 client/index.ts，`<style src>` 同样受支持 | 无额外动作 |
| LSP/IDE | 外部 .scss 不再有 data-v 提示，DX 略降 | 接受；scoped 语义仍由 vue 编译保证 |

## 7. 验收标准

1. **硬门禁（逐字节）**：`dist/style.css`、`dist/index.js` 的 SHA256 与基线 **完全一致**。
   - 这是"外观零变化"的最强可证明依据：CSS 产物没差一个字节 → 渲染层必然等价；JS 产物一致 → 组件注册/模板/脚本零变化。
   - 若出现差异：**禁止继续下一批**。定位差异块（diff dist/style.css），常见原因只有两类——源文件正文没逐字复制（修正后重跑）、或意外改了别的文件（revert 该批）。确认差异仅是 CSS 块顺序时才可接受（此时先人工核对级联影响，再更新基线）。
2. **类型/规范**：tsc（client 双通道）、eslint、biome 全绿。
3. **冒烟点检**（dev console 打开后目视/交互抽查）：
   - /market 页：列表/卡片、搜索、筛选、排序、debug 卡、加载/错误态
   - /dependencies 页：grid/list 布局切换、折叠分组、pending 应用栏
   - 对话框：安装、卸载、bundle 安装/卸载、手动安装、本地上传、确认、安装进度终端、历史、环境快照、忽略更新、本地绑定
   - 状态条：status-right 进度条；滚动条样式（scrollbars 全局）
   - 彩蛋：4 月 1 日图标、恋恋秘密档案动画（若届时可触发）
4. **产物清单**：dist 下仍只有 index.js + style.css（及必要 chunk），无新增资产。

## 9. 边界（本计划明确不做）

- ❌ 不改任何 CSS 规则内容（不合并重复、不清理 dead rules、不调色值/尺寸/间距）。
- ❌ 不重命名 class / CSS 变量 / keyframes。
- ❌ 不拆组件、不动模板与 script、不改 import 图。
- ❌ 不动 `client/styles/` 两个既有全局 scss 的导入方式。
- ❌ 不动 icons（无样式）。
- ⏭ 逻辑下沉（composable/.ts）、组件拆分、死代码清理、i18n 死语言删除 → 后续专项（02-逻辑下沉 等），样式出仓完成后组件拆分将不再受行数牵制。
